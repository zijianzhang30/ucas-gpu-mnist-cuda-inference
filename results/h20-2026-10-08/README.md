- 时间：2026-10-08 21:15:08–21:16:14，北京时间（原始记录使用 UTC）。
- 源码版本：`43b2d44ee1eebdecbedfe03d0196b59a567aafa6`。

- 统计使用程序输出的 CUDA event `kernel_ms` 和 `end_to_end_ms`，不包含 Python 包装脚本、进程启动或文件读取的耗时。前者包括 GPU 归一化和网络算子；后者还包括逐批输入、输出传输及主机端正确数统计。

平台实例未验证整卡独占，未控制设备时钟、功率或其他任务负载。下面是该实例的运行观测，不代表独占 H20 整卡的稳定性能。

## 复现

在仓库根目录、已提供 CUDA Toolkit 和 GPU 的终端执行：

```bash
python scripts/download_mnist.py  # 已有标准 IDX 文件时可跳过
make -B
python benchmarks/run_benchmark.py \
  --executable ./mnist_infer \
  --data-dir data \
  --batch 256 \
  --repeats 10 \
  --build-command 'nvcc -O3 -std=c++17 -gencode arch=compute_80,code=sm_80 -gencode arch=compute_90,code=sm_90 -o mnist_infer src/mnist_infer.cu' \
  --output results/h20-new-run
```

如果 Python 环境没有 PyTorch，包装脚本仍可执行 CUDA 推理，并记录 GPU 环境探测不可用；应另行保存可靠的设备信息。脚本要求每次正确数匹配已发布结果，失败会保留已有记录并退出，不会把失败运行报告为成功。输出目录不能已有 `runs.json`，以免覆盖先前实验。

本次服务器的数据位于项目外层的 `../data`，二进制为 `../mnist_infer_h20`；采用与上面相同的编译参数。原始元数据中的 `build_command` 保留了本次实际编译输出路径。`--build-command` 只记录编译命令，不执行编译。
